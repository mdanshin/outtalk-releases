Настройки: реестр, страница, поиск, режим разработчика

Решение — ADR-0155. Реализованы все четыре этапа: 1 — каркас без смены хранения, 2 — исправления с переносом данных, 3 — контракт настроек плагинов (поля манифеста — строками), 4 — режим разработчика в main, «Параметры запуска», «Внутреннее состояние», пункт меню «Настройки…».

Страница «Настройки» — одна лента разделов, как в VS Code: поиск сверху, оглавление слева, строки настроек справа. Каждая строка описана один раз — в реестре, а значение читает и пишет адаптер поверх прежнего хранилища. Хранилища прежние — те же сторы, те же записи в settings.json и те же скрытые записи в ящике (ADR-0067); этап 2 поменял форму двух записей окна (outtalk-calendar-prefs v5, outtalk-ui v3 — см. «Переносы данных»), формат записей в ящике не менялся.

Страница

  • Шапка. «Настройки», переключатель «Ящик» (кнопки с адресами; с шести ящиков — список), поле поиска (⌘F / Ctrl+F, Escape очищает, «Найдено: N», крестик) и кнопка «Изменённые N» — она вставляет в поиск фильтр @изменённые. Переключатель виден, только когда на экране есть настройка ящика: при обычном просмотре — если в видимой части есть раздел со строкой ящика, при поиске — если она есть среди найденного. Скрытый переключатель места не освобождает (нет прыжка вёрстки).
  • Переключатель «Ящик» — местный для страницы: начинается с ящика, выбранного в приложении, и идёт за ним, если тот сменили; приложение он не переключает. Строки ящика показывают значение выбранного здесь ящика, карточка таких строк начинается шапкой «● Для ящика <адрес>».
  • Оглавление. Разделы в постоянном порядке, плагины — подразделами под «Плагинами» (выключенный — с пометкой «выкл.»). Раздел «Разработчик» — под чертой «Режим разработчика», только в режиме. Текущий раздел подсвечивается по прокрутке — тот, что пересекает линию чтения (четверть высоты ленты, от 32 до 160 px от верха), а у конца ленты — последний видимый. Раздел, выбранный в оглавлении, открытый по ссылке (openSettings('developer'), «Открыть» в подсказке) или тот, внутри которого человек что-то нажал, закрепляется: подсветка остаётся на нём, пока он на экране и пока человек сам не прокрутит ленту (колесо, касание, клавиши прокрутки вне полей ввода, нажатие на полосу прокрутки). Раздел, ушедший с экрана, закрепление теряет. Перестройка ленты закрепление не снимает — когда после седьмого нажатия на версию внизу появляется раздел «Разработчик», подсвечено по-прежнему «О программе»; правило — чистая функция pickActiveSection (settings/toc-active.ts). Переход — сразу, без плавной прокрутки: панели монтируются по мере прокрутки и меняют высоту, плавная прокрутка промахивалась бы.
  • Строка. Название, одна строка описания, элемент справа. Под описанием может стоять тихая пометка адаптера (note, например «Проверка опросом, раз в 1 мин» у «Следить за новой почтой») или, если значение задано параметром запуска (lockedBy), строка с замком «Выключено: задано параметром запуска OUTTALK_…=0» — элемент тогда неактивен, «Сбросить» и «Сделать так же во всех ящиках» недоступны, отметки «изменено» нет. Фиолетовая полоска слева — значение отличается от умолчания. При наведении — «⋯»: «Сбросить» (с подсказкой «станет: …»), «Сделать так же во всех ящиках» (у строк ящика, когда ящиков несколько; разово, с «Отменить»), «Копировать идентификатор»; под пунктами — сам идентификатор. «В других ящиках иначе ›» под строкой ящика переключает «Ящик» на первый ящик с другим значением. Строка уровня «разработчик» в обычном разделе — с меткой «Разработчик» и тёплым оттенком.
  • Карточки. Подряд идущие строки одной группы — одна карточка; без группы строки делятся по области (приложение / ящик). Строки «Дополнительно» уходят в конец своей карточки под свёрнутый заголовок со счётчиком; при поиске они показываются наравне с остальными.
  • Плагин. Карточка: значок, имя, версия, «В составе OutTalk», описание, переключатель «Плагин <имя>»; под шапкой — строки полей манифеста, внизу — «Проверить подключение», если плагин её объявил. Подробно — «Плагины: строки из манифеста».
  • Подсказка в правом нижнем углу (settings-toast) — только для нажатий на номер версии и массовых действий. Простые значения применяются сразу и подсказок не показывают. Стоит с отступом 24 px от края окна и не шире 420 px, поэтому не закрывает оглавление; у ленты снизу запас прокрутки, и последние строки всегда можно поднять выше подсказки. Прячется сама: без кнопки — через 2,6 с, с кнопкой («Открыть», «Отменить») — через 3,2 с (toastDuration); пока на подсказке курсор или фокус клавиатуры, отсчёт стоит (и продолжается с того же места), так что кнопку можно нажать спокойно.

Плагины: строки из манифеста

С этапа 3 отдельной формы плагина с кнопкой «Сохранить» нет: каждое поле contributes.settings — обычная строка реестра (plugin.<id>.<key>) с поиском, «изменено», «Сбросить» и «Дополнительно». Контракт полей, пределы и проверки main — Архитектура плагинов → Настройки плагина.

Вид поляСтрока на странице
toggleпереключатель; в main хранится строкой on / off поля
choiceкнопки (до 4 вариантов; больше — main ещё при проверке делает из поля select)
selectвыпадающий список
numberчисловое поле с границами min…max и шагом; число вне границ не записывается — под полем красная подсказка «От min до max» (связана с полем через aria-describedby). Подсказка лежит поверх нижнего отступа строки, а не в потоке, поэтому поле и строка не сдвигаются
text, urlполе ввода; записывается по уходу из поля или по Enter, Esc возвращает сохранённое; ошибка main (например, адрес не по https://) — под полем, сохранённое не меняется
secret«Сохранён · Заменить / Удалить» (или «Задать», пока не сохранён). «Заменить» открывает поле пароля с «Сохранить» и «Отмена»; «Удалить» спрашивает «Удалить сохранённое?» на месте. Значение в окно не приходит никогда; введённое стирается из поля, как только main его сохранил
  • Описание, «Подробнее», ключевые слова. description — строка описания под названием, help — свёрнутое пояснение «Подробнее» под ним, keywords и имя плагина — слова для поиска. Всё это — только обычный текст: страница не разбирает в нём ни HTML, ни Markdown.
  • «Дополнительно» (advanced) — строка уходит в конец карточки под свёрнутый заголовок, как у настроек ядра; при поиске видна наравне с остальными.
  • Условие показа (when) — строка видна, только пока поле выше равно (или не равно) значению. Пример — Jira: «Логин Jira» только при «Способ входа: Логин и токен», поля команды и «Лимит нагрузки» — только при «Роль: Руководитель». Скрытая строка не находится поиском.
  • Выбор без умолчания. У select / choice без default первым вариантом стоит «Не выбрано»: строка не выдаёт чужой вариант за выбранный.
  • Поле ящика (scope: 'mailbox') — значение показывается и пишется для ящика из переключателя «Ящик» (снимок plugin:getSettings(id, accountId)), карточка таких строк — с шапкой «● Для ящика <адрес>». «Сделать так же во всех ящиках» у строк плагина нет: значения соседних ящиков страница не загружает, и «Отменить» было бы нечем вернуть. Удалённый ящик забывает свои значения: main — в файлах плагинов (forgetPluginAccount), окно — снимки (forgetRoamingAccount). Секрет по ящикам не делится. Из встроенных плагинов поле ящика пока не объявил ни один.
  • Выключенный плагин. Строки видны и находятся поиском, но менять их нельзя: под шапкой — «Сначала включите плагин — тогда его настройки можно будет менять.» (plugin-off-note), элементы неактивны, «Сбросить» недоступно, «Проверить подключение» — тоже, с той же подсказкой. До этапа 3 выключенному плагину настройки можно было задать заранее.
  • «Проверить подключение» — внизу карточки, если манифест объявил verifyCapability; вызывает её через plugin:invoke и показывает ответ плагина обычным текстом (зелёным — подключено, красным — ошибка). При поиске нижняя строка скрыта.
  • Откуда значения. При открытии страницы для каждого плагина с полями читается снимок местным каналом plugin:getSettings (для полей ящика — ещё и для выбранного ящика); сервер почты при этом не трогается. Ответ каждой записи становится новым снимком.

Меню «Настройки…»

Пункт «Настройки…» (id: 'app-settings', сочетание ⌘, на macOS и Ctrl+, в Windows и Linux) открывает страницу настроек в главном окне, из какого бы окна его ни вызвали: на macOS он стоит в меню приложения (после «О программе»), в Windows и Linux — в новом меню «Файл» (там же «Выход»). Main шлёт menu:action openSettings только главному окну и поднимает его; окно вызывает openSettings() (lib/useMenuActions.ts), даже если открыт редактор письма.

Переносы данных (этап 2)

Каждый перенос сохраняет прежнее значение; проверяется тестами на настоящих записях прежних версий (store/useCalendarPrefs.per-mailbox.test.ts, store/useCalendarPrefs.super-vip.test.ts, store/useUi.v3.test.ts).

outtalk-calendar-prefs v4 → v5 — рабочий день и цвета событий по ящику (ADR-0155 п. 6). До v5 цвета правил и рабочий день были общими на приложение, а срез OutTalk.CalendarPrefs писал общее значение в копию КАЖДОГО ящика и возвращал копию ящика в общее — побеждал ящик, синхронизированный последним, и его значение потом уезжало в соседние.

  • Новая форма: categoryColorsByAccount, workDayByAccount (ключ — calendarPrefsAccountKey, только свои значения ящика), прежние manualColorsByAccount и vipByAccount без изменений, буфер legacyCalendar. Карты цветов и рабочего дня — не больше 64 ящиков.
  • migrateCalendarPrefs: общие цвета и рабочий день уходят в буфер legacyCalendar. Пока буфер есть, ящик без своих значений показывает его (categoryColorsOf / workDayOf: своё → буфер → умолчание) — ни одно окно не мелькнёт умолчанием.
  • Когда главное окно впервые получило список ящиков (App.tsx, useAccounts.loaded), adoptLegacyCalendar(ids) копирует буфер каждому подключённому ящику, у которого ещё нет своих значений (значение, уже приехавшее из ящика, побеждает), и удаляет буфер. Ящик, подключённый позже, получает умолчание: 08:00–18:00 и «Все встречи» — зелёный. Пустой список (нет ни ящиков, ни демо) буфер не трогает.
  • Срез calendarSlice читает и пишет только ящик accountId: read — mailboxCalendarOf (null, если у ящика нет ничего своего и буфера нет — тогда копия в ящике побеждает), apply — replaceMailbox (тот же разбор, что у файла настроек: копия недоверенная). Формат записи в ящике прежний: { categoryColors, workDayStart, workDayEnd, manualColors, vip }. Перенос буфера не выглядит местной правкой: срез уже читал буфер как значение ящика, поэтому ни новый штамп, ни отправка в ящик от переноса не случаются.
  • Неделя, день, месяц, карточка встречи и подкачка участников для цвета VIP читают значения ящика, чей календарь показан (useCategoryColors(accountId), useWorkDay(accountId)).
  • Удалённый ящик (forgetRoamingAccount, ADR-0078) забывает всё календарное: useCalendarPrefs.forgetAccount.
  • Правка ящика, который не выбран в приложении (переключатель «Ящик» на странице), уходит в его ящик, когда ящик выберут: lib/roaming.ts при выборе ящика видит, что значение отличается от запомненного, ставит свежий штамп и после чтения копии отправляет её. Раньше движок восстанавливал запомненное и откатывал такую правку — пережиток срезов с одним значением на всё приложение (касалось и подписи, и бесед).
  • Старая версия на другом компьютере продолжает писать общее значение в копию выбранного ящика — у неё прежнее поведение; новые версии сходятся по ящику.

outtalk-calendar-prefs v5 → v6 — супер-VIP (ADR-0161). Новое поле superVipByAccount — ручной уровень супер-VIP по ящику (тот же ключ calendarPrefsAccountKey, тот же разбор normalizeVip, что у vipByAccount).

  • Правило: каждая запись супер-VIP есть и в vipByAccount того же ящика. setSuperVip(…, true) сначала кладёт запись в ручной VIP (прежний предел 100 записей; отдельного предела у супер-VIP нет; false, если список полон), removeVip снимает и уровень, разбор файла (sanitizeSuperVipByAccount) выбрасывает супер-VIP без такого же VIP, forgetAccount забывает и уровень.
  • migrateCalendarPrefs: запись v5 получает пустую карту superVipByAccount: {}; ручной список VIP не меняется.
  • Совместимость назад. Версии без супер-VIP читают vipByAccount как раньше и видят этих людей обычными VIP — ручной список не теряется и не портится. Поэтому уровень хранится отдельным полем, а не отметкой внутри списка (*адрес): прежний разбор принял бы такую запись за годный адрес.
  • Срез OutTalk.CalendarPrefs везёт поле superVip рядом с vip: { categoryColors, workDayStart, workDayEnd, manualColors, vip, superVip }; прежние версии лишнее поле пропускают. parse принимает superVip только массивом строк, иначе — undefined. В replaceMailbox: пришла копия с полем — оно решает (сверенное с vip копии); копия без поля (её записала прежняя версия) — свой уровень на этом компьютере остаётся, сверенный с пришедшим vip. Если прежняя версия сняла человека из VIP, снимется и супер-VIP; уровень, записанный здесь, на компьютере с прежней версией не виден.
  • Полнота реестра: superVipByAccount → people.vipManual в таблице CAL_COVERED (settings/registry.test.ts).
  • Тесты — store/useCalendarPrefs.super-vip.test.ts (перенос v5 → v6, запись v6 глазами прежней версии, копия в ящике с полем и без), обновлён useCalendarPrefs.per-mailbox.test.ts.

outtalk-ui v2 → v3 — способ проверки отдельно, тема «Как в системе» (ADR-0155 п. 7, 8).

  • Новое поле notifyTransport ('stream' | 'poll'): poll, если был выбран опрос, иначе stream. notifyMode не меняется и остаётся тем, что читает наблюдение в App.tsx (путь почты не тронут): пока наблюдение включено, notifyMode === notifyTransport, выключенное — 'off'. setNotifyWatching(on) включает выбранный способ, setNotifyTransport меняет способ (у выключенного наблюдения — только запоминает). Выключил и включил — вернулся прежний опрос (на этапе 1 включение давало «Мгновенно»). У профиля, где наблюдение было выключено ещё до v3, прежний способ не сохранялся — включение даст «Мгновенно» (main сам перейдёт на опрос, где поток не держится).
  • Тема: theme — 'light' | 'dark' | 'system'. Сохранённая тема не меняется (запись без темы — прежняя тёмная); «Как в системе» — умолчание только новой установки.

Тема «Как в системе»

  • Где выбирается. «Внешний вид › Тема»: «Светлая · Тёмная · Как в системе». Кнопка внизу левой панели — быстрый переключатель той же настройки: нажатие всегда меняет видимую тему, из «Как в системе» — на тему, обратную нынешней системной, и выбор становится явным (подсказка у кнопки: «… · сейчас как в системе»). Вернуть «Как в системе» — в Настройках.
  • Как работает. useThemeSync (lib/useTheme.ts, в каждом окне) отправляет выбор в main (theme:set); main ставит nativeTheme.themeSource и отвечает, тёмная ли тема сейчас (shouldUseDarkColors) — окно сразу рисует нужную. Дальше окно слушает prefers-color-scheme: Chromium меняет его вслед за системой (событие updated у nativeTheme), поэтому отдельный канал «тема системы сменилась» не нужен. Не сохраняемое поле systemDark в useUi и селектор resolvedTheme дают тему, которой окно нарисовано; её читают все места, где нужна именно видимая тема (цвета событий, тёмный режим письма, тема плагина env.theme — по-прежнему light / dark).
  • Сквозные тесты. OUTTALK_SYSTEM_THEME=light|dark подменяет тему системы — только в неупакованной сборке (main/windows/theme-source.ts); playwright.config.ts ставит dark, чтобы чистый профиль не зависел от темы машины.

«Люди и VIP › Как выделять»

Решение — ADR-0164. Как вид применяется к окнам (переменные и атрибуты на <html>, CSS) — в «Интерфейс», раздел VIP и супер-VIP; граница кадра «Задач» — в «Архитектура плагинов» и «Безопасность».

Подраздел о том, как выглядят VIP и супер-VIP; кого считать VIP — по-прежнему раздел «Люди и VIP» над ним. В оглавлении — дочерней строкой под «Люди и VIP» со значком искры, над заголовком — путь «Люди и VIP › Как выделять», рядом с заголовком — метка scopeNote с ноутбуком «На этом компьютере · для всех ящиков».

Хранение. Стор useVipLook (store/useVipLook.ts), запись outtalk-vip-look (версия 1) в settings.json этого компьютера через mainSettingsStorage; сохраняется только поле look. Файл настроек — недоверенный ввод: merge пропускает сохранённое через sanitizeVipLook (lib/vip-look.ts) — неизвестные слова, не-булевы флаги и негодные коды цвета дают умолчание, своя палитра короче трёх цветов отбрасывается целиком. Тот же разбор проходит каждая запись patch. Пишет только главное окно (ADR-0104); остальные окна читают выбор при открытии. Ни один срез roaming-slices.ts запись не читает — она не уезжает в ящик.

Широкие элементы (плашки, свой цвет, своя палитра) рисуются под названием строки во всю ширину (SettingRow wide), а не справа. В обычной строке (не wide) колонка названия и описания держит не меньше 240 px: элемент справа, которому не хватает места (поле текста, поле секрета с кнопками, номер сборки), переносится под описание и прижимается вправо, а узкие (переключатель, выбор кнопками, число) остаются в строке.

Защита читаемости. Свой цвет и своя палитра не попадают в CSS как есть: deriveVipColor и deriveSvStops выводят варианты для светлой и тёмной темы и для букв, сдвигая светлоту до порогов контраста (READABILITY: свет 1,7:1 на светлой и 3,5:1 на тёмной, буквы 4,5:1, точки палитры 1,5:1 и 4,5:1). Если исходный цвет на какой-то теме почти не виден, под редактором — пометка «На светлой теме этот цвет почти не виден — там он берётся темнее» (или «…светлее» для тёмной), иначе — «Читается в обеих темах» (vip-look-readability).

Скорость. Ни один элемент подраздела не обращается к main: бюджет открытия страницы (settings-open-budget.test.tsx) не изменился.

Полнота. Новый стор — в таблице «каждый сохраняемый стор учтён» ('outtalk-vip-look'), а отдельный тест полноты сверяет: каждое поле VipLook — ровно своя строка people.look.* (поле at — семь строк), у каждой scope: 'app', sync: 'device', умолчание реестра равно умолчанию стора. Тесты адаптеров: запись через стор, сброс одной строки, списки VIP нетронуты, «Свой» засевает цвет и палитру, мусор (url(x), один цвет вместо трёх) отвергается.

Поиск

Чистая функция searchSettings(all, query, opts) работает по тексту описаний, а не по смонтированным панелям.

  1. Ступени (RANK): точный идентификатор — 100, название — 50, ключевые слова — 30, описание — 15, подписи вариантов и поля панелей — 8. Должны найтись все слова запроса; очки складываются.
  2. Сравнение: без регистра, «ё» = «е», по началу слова (и части слова после -, /, .). Для слов от пяти букв — ещё и по основе без русского окончания («подпись» находит «подписи», «Подписывать»), на ступень тише точного совпадения.
  3. Раскладка. Если по запросу ничего нет, он повторяется в другой раскладке: ntvf → «тема».
  4. Фильтры: @изменённые / @измененные / @modified, @ящик / @mailbox, @плагин:<имя> / @plugin:<имя>.
  5. Уровни. Настройки developer без режима разработчика не находятся никак — даже по точному идентификатору. advanced находятся всегда. Строка, скрытая условием when (например, редактор подписи при выключенной подписи), не находится.
  6. Подсветка — highlightParts: начало слова, совпавшее со словом запроса или его основой (<mark>, токен --mark-bg).

Оглавление при поиске показывает только разделы с находками и их число; найденное поле панели показывается под строкой «Найдено: …» (например, запрос «супер» находит пункт people.vipManual.super «Супер-VIP» панели «VIP вручную», ADR-0161).

Режим разработчика

Режим разработчика — видимость, а не права. Он показывает раздел «Разработчик», служебные строки в других разделах («Способ проверки», «Интервал опроса») и пункт меню «Вид → Диагностика подключения» — и больше ничего. Он не включает инструменты разработчика в выпускной сборке (они по-прежнему только !app.isPackaged || OUTTALK_DEBUG), не ослабляет TLS, CSP, песочницу и проверки IPC, не открывает секретов, не включает тестовую ленту обновлений. Каналы, которые он делает видимыми (журнал, проверки, параметры запуска, внутреннее состояние), сами проверяют, что их зовёт главное окно, — с режимом или без; main нигде не читает флаг как разрешение.

  • Включение. Семь нажатий (мышью или Enter) на номер версии в «О программе», не дольше 3 с между нажатиями. С четвёртого — подсказка «Ещё 3 нажатия… и включится режим разработчика» с точками прогресса (сколько из семи уже нажато), на седьмом — «Режим разработчика включён» с кнопкой «Открыть» (переходит к разделу). Нажатия при включённом режиме отвечают «Режим разработчика уже включён».
  • Выключение — переключатель «Режим разработчика» в разделе «Разработчик».
  • Включение на один запуск — параметр запуска OUTTALK_DEBUG (как и раньше, он же открывает инструменты разработчика). Пока он задан, переключатель неактивен с пометкой «Включено: задано параметром запуска OUTTALK_DEBUG», «Сбросить» недоступно, а сохранённый выбор не меняется: без параметра следующий запуск вернётся к нему.
  • Что ещё зависит от режима. Пункт меню «Вид → Диагностика подключения» (⌥⌘ / Ctrl+) виден только в режиме: main пересобирает меню при каждом включении и выключении. Окно диагностики по-прежнему открывается и кнопкой в «Разработчик › Журнал».

Раздел «Разработчик»

  • «Режим разработчика»; «Номер сборки» (версия · сборка, с копированием).
  • «Журнал»: «Окно диагностики» (кнопка «Открыть»/«Закрыть» и сочетание ⌥⌘ / Ctrl+) и «Подробный журнал» (тот же переключатель, что в панели диагностики, с «ещё N мин», ADR-0144).
  • «Проверки»: «Задачи Exchange», «Доступ к ящику», «Надстройки Outlook» — строкой с кнопкой «Проверить»; карточка проверки раскрывается под строкой и только тогда монтируется; сама проверка, как и раньше, начинается своей кнопкой.
  • «Параметры запуска» (developer.environment, панель env-readout) — таблица заданных в этом запуске параметров OUTTALK_*: имя, значение или «задано», что делает; под ней — «Только для чтения — задаются при запуске программы.» и строка о том, доступны ли инструменты разработчика (devtools-availability: «доступны (⌥⌘I / Ctrl+Shift+I)» или «в этой сборке выключены; режим разработчика их не включает»). Main (developer:environment, main/developer/environment.ts) отдаёт только имена из своего списка; значение — только у перечислимых флагов и только из ожидаемого набора (OUTTALK_LOG=debug, OUTTALK_KEEPALIVE=1, OUTTALK_SYSTEM_THEME=dark…); пути к файлам, номер сборки, OUTTALK_DEBUG и всё неожиданное — «задано» (value: null). Остальное окружение процесса в окно не уходит.
  • «Внутреннее состояние» (developer.internalState, панель internal-state) — что программа запомнила сама, с подтверждением на месте («Сбросить» → вопрос → «Да» / «Нет»):

Каналы раздела (main/ipc/developer.ts) — только главное окно (developer:state — любое известное окно) и не проверяют режим: режим их только показывает. Подробно о границе — Безопасность.

Скорость: открытие без запросов к серверу почты

  • Отдельный кусок бандла (LazySettings, как «Документация» в ADR-0146): главное окно грузит страницу по первому открытию, второстепенные окна — никогда.
  • Панели с данными main монтируются, когда видны (WhenVisible): каталог VIP, сертификаты, надстройки, хранение задач, «О программе», подробный журнал, «Параметры запуска», «Внутреннее состояние». Снимки значений плагинов читаются одним местным plugin:getSettings на плагин при открытии страницы. Строки поверх сторов renderer рисуются сразу — им ничего не нужно спрашивать.
  • Надстройки Outlook читаются из сохранённого: addins:settings(id, { refresh: false }) — main не трогает источник каталога вообще. С сервера список обновляется кнопкой «Обновить список» ({ refresh: true } — прежнее обновление раз в 10 минут) или как раньше — при открытии редактора встречи. Список, ещё ни разу не приходивший с сервера, так и говорит. Разбор opts — main/addins/settings-opts.ts: ничего или { refresh: boolean }, всё прочее — отказ, а не молчаливое «обновить».
  • Проверки не монтируются, пока не нажато «Проверить».
  • Охрана — pages/settings-open-budget.test.tsx: вся страница рисуется с записывающим window.api в худшем случае (в jsdom нет IntersectionObserver, и все ленивые панели монтируются сразу), режим разработчика включён. Каждый вызов моста — из списка местных каналов (settings.*, plugins.list / getSettings / todoStorage, addins.settings только с { refresh: false }, directoryVip.status / addresses, smime.list, diag.verboseLog, в режиме разработчика — developer.state (копия флага в preload, даже не канал), developer.environment и developer.internalState (местные каналы main), подписки на события; update.check — сервер обновлений, не почты, как и прежде при открытом «О программе»). Ни одного mail.*. request-budget.test.ts не менялся: провайдеры не тронуты.

Как добавить настройку

  1. Описание в CORE_SETTINGS (settings/registry.ts): идентификатор вида раздел.что, раздел, название и одна строка описания по-русски простыми словами, ключевые слова (RU и EN), область и где живёт значение, видимость, умолчание.
  2. Адаптер в ADAPTERS (settings/adapters.ts) поверх стора; у настройки ящика — forgetAccount.
  3. Новое сохраняемое поле стора — в таблицу полноты settings/registry.test.ts (настройка или «не настройка» с причиной). Без этого тест упадёт — это и есть защита от настроек «мимо страницы».
  4. Переносится через ящик — опора на срез в lib/roaming-slices.ts и строка в таблице ROAMED того же теста.
  5. Значение может задать параметр запуска — lockedBy у адаптера (обёртка lockable в adapters.ts): строка только для чтения, запись и сброс отказывают, сохранённый выбор человека не трогается. Список таких строк закреплён тестом реестра.
